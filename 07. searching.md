# Scope

This note records parameters. The step-by-step procedure for running a search on each portal is in [09. lessons](09.%20lessons.md), and what each preference field does at the query is in [08. scoring](08.%20scoring.md).

Searches run from the query matrix, `queries.yaml` in the code repository, which is the compiled form of [04. preferences](04.%20preferences.md). One query per role per location per portal. The collector runs the matrix verbatim. It refuses to sweep while `queries.yaml` carries `approved: false`, which is the flag the user flips by hand after reading the matrix.

A query carries role keywords, location, freshness, and seniority, each in the portal's own form. No other filter goes in, though the URL also carries sort order and a pagination offset.

# LinkedIn

The collector reads the endpoint, not the search URL. Both are recorded, since the search URL is still the human link.

## The endpoint

Verified 2026-09-30.

```
https://www.linkedin.com/voyager/api/voyagerJobsDashJobCards?decorationId=com.linkedin.voyager.dash.deco.jobs.search.JobSearchCardsCollection-220&count=25&q=jobSearch&query=(origin:JOB_SEARCH_PAGE_OTHER_ENTRY,keywords={kw},locationUnion:(seoLocation:(location:{loc})),selectedFilters:(sortBy:List(DD),experience:List(2,3,4),timePostedRange:List(r{seconds})),spellCorrectionEnabled:true)&start={start}
```

| Parameter | Meaning | Evidence |
|---|---|---|
| `keywords` | same semantics as the search URL | the page sends the search box value verbatim |
| `locationUnion.seoLocation.location` | country, or city with country | `metadata.geoUrn` resolves it |
| `timePostedRange:List(r<seconds>)` | posting age in seconds | `r172800` honoured |
| `experience:List(2,3,4)` | seniority codes | carried from the 2026-09-19 filter panel reading |
| `sortBy:List(DD)` | newest first | accepted |
| `count`, `start` | 25 per request, offset paging | `start` 0, 25, 50 each returned 25 |

`paging.total` is the claimed count and the records are in `included`. Fields, headers and the token are in [09. lessons](09.%20lessons.md). Every field is typed, so nothing is parsed from rendered text.

## The search URL

Verified 2026-09-18 and 2026-09-19. This is the human link and no longer what the collector fetches.

```
https://www.linkedin.com/jobs/search/?keywords={kw}&location={loc}&f_TPR=r{seconds}&f_E=2,3,4&sortBy=DD&start={offset}
```

| Parameter | Meaning | Evidence |
|---|---|---|
| `keywords` | unquoted, matched against the whole posting | the same query returned 3 results quoted and 215 unquoted |
| `location` | country name, or city with country | the filter pill shows the resolved location |
| `f_TPR=r<seconds>` | posting age, custom values accepted | `r172800` cut a week's 3 results to 1 |
| `f_E` | experience level, multi-select | read from the filter panel on 2026-09-19. 1 Internship, 2 Entry, 3 Associate, 4 Mid-Senior, 5 Director, 6 Executive |
| `sortBy=DD` | newest first | accepted |
| `start` | pagination offset, 25 per page | accepted |

A result card carries title, company, location, posting age, and the numeric id from `urn:li:jobPosting:`, which is the dedup key. A single query reaches about 1000 results, so a claimed count at that cap means the cell is not fully reachable.

An industry facet exists, `f_I` with numeric codes. It works: `f_I=17` produced a Medical Equipment Manufacturing filter pill and `f_I=52` changed the result set. It is deliberately unused, because it filters on the industry the employer declared for its own company page, which misses consultancies and mislabelled companies.

# Naukri

The collector navigates the search URL below and reads the `jobapi/v3/search` response the page fetches for itself. A direct call is refused with HTTP 406 `recaptcha required`, since the page signs each request with an `nkparam` header. Response fields are in [09. lessons](09.%20lessons.md).

Verified 2026-09-19 for the URL, 2026-10-01 for the response.

```
https://www.naukri.com/{kw-hyphenated}-jobs-in-{city}?jobAge={days}
```

| Parameter | Meaning | Evidence |
|---|---|---|
| keyword and city | in the URL path | the page header echoes both |
| `jobAge` | posting age in days | 1 and 7 work and show a chip. 2 is ignored silently, with no chip and no change in the count |
| `experience` | returns jobs whose required range contains this number of years | `experience=2` cut the count from 1908 to 250 and every card's range contained 2 |

Salary is a facet with fixed bands, 15-25, 25-50, 50-75 and 75-100 Lakhs. Its URL parameter was never captured and is not needed, because compensation is never filtered at the query.

Two role slugs degrade. `R&D Engineer` becomes the tokens "r d engineer" and returned 12 results, and `C++ Developer` becomes "c developer" and returned 9. Their portal-native forms are still to be found. Open.

# Stepstone

The collector navigates the URL below and reads the postings from the page's own `window.__PRELOADED_STATE__`, which carries an exact `datePosted`. Stepstone exposes no API in its network responses. Fields are in [09. lessons](09.%20lessons.md).

Verified 2026-09-18 and 2026-09-19 for the parameters, read from the portal's own facet links and confirmed against the counts. State reading verified 2026-10-01.

```
https://www.stepstone.de/jobs/{kw-hyphenated}/in-{place}?ag={age}&page={n}
```

| Parameter | Meaning | Evidence |
|---|---|---|
| `ag=age_1` or `ag=age_7` | newer than 24 hours, or newer than 7 days | facet links, and counts of 245 against 1846 |
| `page` | pagination, 25 genuine results per page | facet links |
| `wfh=1` or `wfh=2` | work-from-home facet, unused because workplace type is not sent at the query | facet links |
| `fdl=en` or `fdl=de` | language the portal detected in the posting | facet links |
| `di=<discipline>` | discipline facet | facet links |

Stepstone has no seniority facet. The full list the results page has is age, application method, detected language, disciplines, numeric skill ids, work-from-home and worktypes. Salary appears on the page as a display, not as a filter link.

`R&D Engineer` degrades here as well, reading back as "R D Engineer". Open.
