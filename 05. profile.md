## The evidence base

The eleven points above are a summary. They are not what a document is written from. [knowledge/](knowledge/) holds the evidence, one note per project, employment or skill, and a claim in a CV or a letter traces to a note there or it does not go in.

Each note carries five frontmatter fields.

| Field | Meaning |
| --- | --- |
| `type` | skill, project or learning |
| `level` | exposure, working, strong or expert |
| `last-used` | when the work was last done, so a stale claim is visible |
| `evidence` | where it is proven, being an employment, a project, a repository or a certificate |
| `cv-ready` | whether a generator may cite it at all |

Three conventions make the notes usable rather than decorative.

1. `cv-ready: true` is the licence to cite. A note without it exists for context and interview preparation, and no document draws on it.
2. A note records what is **not** evidenced as explicitly as what is. The ball balancer note states that SPI is absent from that repository and that the network emulator is an in-process ring buffer rather than an injector on the wire. The thesis note states there is no ONNX work and no custom quantisation calibration set. These lines are the reason a generator does not reintroduce a plausible claim, and they cost a reading of the primary source to establish.
3. A note is corrected in place and the correction overrules its own earlier text. The ball balancer note rejects its own "stable at 5 to 7 ms" line, because the results file shows no degradation through 10 ms and breakdown by 20 ms. Where a note and a repository disagree, the repository wins.
