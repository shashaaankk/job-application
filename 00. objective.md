# Objective

A scheduled pipeline that searches job portals, screens what it finds against the user's preferences and profile, and puts every posting that survives onto the board as a card. He reads the cards and moves the ones worth applying to into the `to apply` column, which is what releases them to a tailored CV and cover letter. He applies. The pipeline does the searching, the screening, the documents and the bookkeeping, and he does the judging.

# What it has to get right

1. Each run returns a shortlist with few false positives and few missed fits.
2. The pipeline runs on a schedule without being re-taught. Every criterion and procedure lives in this vault.
3. Degradation is visible. Run logs record what each source returned, and coverage is checked mechanically rather than trusted.
4. Generated artifacts contain only facts from the profile. No fabrication.

# Rules

1. Behaviour is written down. Rubrics, filters, and procedures live in the vault as skills and notes, so a run is reproducible and tunable instead of being left to model judgement or memory.
2. Knowledge notes use Google's Open Knowledge Format, which is markdown with YAML frontmatter carrying provenance and freshness. The specification is at https://github.com/GoogleCloudPlatform/open-knowledge-format.
3. Rejecting rules live in one place, namely `scripts/screen.py`, and they reject rather than rank. Nothing a run produces grades a posting.
4. Python does the mechanical work. Model judgement is spent on writing documents and checking them, and his own judgement decides which postings get them.
5. The pipeline never submits an application.
